# What Macha does that Dannan and Dagda must do, and Macha must still do

**Baseline moved, 2026-11-05: Macha `develop` at `cac5998`, tag 0.92.4 on `70cf4a4`.** Citations below were read at `00861dd`. In the moving files only `src/cluster/cluster.cpp` (from about `:225`), `cluster.hpp` (from `:122`), `net.cpp` (one line moves at `:2304`, a net shift of one after it) and comments in `src/types.hpp` and `src/config.hpp` changed, so those line numbers are off by a few, not re-cited. Read a copy at `build/scratch/macha-cac5998`.

Status: inventory, re-based 2026-11-05 on a read of Macha at `00861dd`
(0.92.3, the baseline; the first read was at `6c7ec64`, 0.91.2), against
Dannan's tree on `feature/macha-parity`. Macha's code is the source of truth:
where a row and the code differ, the code wins. One row per behaviour of the
code the design places in Dannan or Dagda, with where it lives in Macha, what
gates it there, and what proves it here. Each row is read twice: it is the
specification of a `dannan_tests` or `dagda_tests` case written here (a build
step that cannot name the row's case does not ship); and its Macha case is the
gate of the port step that replaces the piece in Macha (a port step that cannot
name the proof for a behaviour it touches does not happen). The "Where" column
is Macha's location, read for what the code does and never copied.

How to read the columns:

- **Where** is `file:line` under Macha's `src/` at `00861dd`, found by opening
  the code in the extract at `build/scratch/macha-00861dd`. Paths outside `src/`
  say so.
- **Macha's gate** names Macha's own cases. Every name was checked to exist at
  `00861dd`. Unprefixed case names are in `tests/test_rpc_cluster.cpp`, group
  `rpc_cluster`; `invariants/` cases are in `test_invariants.cpp`. A bare test
  file means the suite owns the invariant and the case is still to be named.
  Gates named `VALIDATION` are in `macha/VALIDATION.md`; `crash matrix` is
  `macha/docs/durability.md`.
- **Dannan case** names cases in `dannan_tests`. Every one was opened, and its
  body read, on 2026-11-05. Not quite every one: a few cited cases, such as `Crypto.AesGcmRefusesAnyAlteration` and `Upnp.ReadsSoapValuesAndFaults`, were only checked to exist, and some files were read in part.
- **Status** is about Dannan and nothing else. **proven**: the named cases
  assert the whole behaviour. **partial**: they assert some of it, and the cell
  says what is missing. **none**: no case asserts it. **Macha's**: the row stays
  in Macha and Dannan owes nothing for it. A count or limit a row states that the
  cases only reach through a named constant is called missing: the constant was
  read equal to Macha's, but changing it would fail no case.

Dannan has its own wire, versions 1 and 2, by Tom's decision (2026-11-03 night);
that it does not speak protocol 23 is not a gap anywhere below. Its state files
and its `NodeRecord` are its own for the same reason, and the fields Macha keeps
in `NodeInfo` are adverts (`2026-11-04-macha-parity.md`, opening).

## What changed in Macha since `6c7ec64`

Read from `git diff 6c7ec64 00861dd`, sixteen commits. The Macha session's claim
that nothing else in the transport or control plane changed holds:

- `cluster/net.cpp` changed only for 0.91.3's reply rule (`d61eb02`): the
  `reply_not_sent` substitute, its bound, both `queue_message`, and
  `RpcServer::execute` closing a session when no answer can be queued.
  `cluster/net.hpp`, `cluster.*`, `membership.*`, `placement.*`, `telemetry.*`,
  `public_connectivity.*`, `subsystem/` and `contract/work.*` are untouched.
- 0.91.4 changed documentation and `macha.yaml.example` and no source.
- 0.91.5 (`0342ea3`): `StorageUnavailable`, thrown by the store and read by
  ingest. The store's and Macha's own.
- 0.92.0 to 0.92.2: books. New `config` keys and API routes, Macha's own; no new
  call into the network layer but `node_.config()`.
- 0.92.3 (`8e0308e`): the claim guard, repair's list versions, the scan wait
  before the object lock, the held ledger's seed order, the torrent removal
  clock and the delta decoder's key rule. All in the store's rows.

From this read, 2026-11-05. Reported, not fixed; each needs a ruling or a case.

- **A job queued for a session that has closed runs here and not in Macha.**
  `RpcServer::execute` returns without calling the handler when its session is no
  longer ready (`cluster/net.cpp:4404`-`:4409`; `ready` falls at `:4396`). Dannan's
  `RequestScheduler` holds only a `Reply`, a weak reference, and nothing removes
  or skips a job when its session closes (`net/server.cpp:191`,
  `net/scheduler.cpp:185`): the handler runs and its reply goes nowhere. A peer
  going away therefore leaves its queued work running. No case covers it.
- **An empty failure domain differs.** Macha fills an empty `failure_domain` with
  the node's host (`cluster/cluster.cpp:38`), so two nodes on one host with none
  configured share a domain. Dannan copies it as it is (`node.cpp:32`), and
  placement then gives each node a domain of its own (`placement/placement.cpp:162`).
  Macha's facade can pass the host itself; if it does not, placement differs. Tom's
  rule says Dannan changes.
- **Unknown configuration keys.** Macha refuses them at start (`config.cpp:964`);
  Dannan's `config::Reader` warns. This binds no port, since Macha keeps its own
  configuration, but it is a difference in Dannan's own executable.
- **The transport's numbers are pinned nowhere.** 256, 128 MiB, 512 and the small
  reserve are read equal to Macha's and asserted only by name, so a change to one
  fails no case.
- **Cases against the sans-I/O layers stand in for the live ones** in the channel,
  reply-rule and socket-option rows above: the layer is proven, the session or
  socket path that uses it is not.
- The dropped-replies finding of 2026-11-03 is fixed in Macha at 0.91.3 and is now
  the last row of the transport table.
- `availability/test_a_disk_coming_back_is_surveyed_without_a_namespace_change`
  was flaky on the laptop at `6c7ec64`: it failed 1 run in 5 on the untouched
  0.91.2 test source, and in both full-gate runs on the branch. Not re-run here.
